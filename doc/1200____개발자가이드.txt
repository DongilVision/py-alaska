1. 시작하기
================================================================================

1.1 최소 구성
--------------------------------------------------------------------------------

  프로젝트 구조:
    my_app/
    ├── config.json       ← 설정 파일
    ├── main.py           ← 진입점
    └── tasks.py          ← Task 클래스

  config.json:
    {
      "app_info": {
        "name": "my_app",
        "id": "my-app-001",
        "version": "1.0.0"
      },
      "task_config": {
        "worker/MyTask": {
          "@import": "tasks"
        }
      }
    }

  tasks.py:
    from py_alaska import task

    @task(mode="process")
    class MyTask:
        def run(self):
            while self.running:
                print("working...")
                time.sleep(1.0)

  main.py:
    from py_alaska import TaskManager, gconfig

    gconfig.load("config.json")
    with TaskManager(gconfig) as manager:
        manager.wait()


1.2 실행
--------------------------------------------------------------------------------

    python main.py


2. @task 데코레이터
================================================================================

2.1 기본 사용법
--------------------------------------------------------------------------------

    from py_alaska import task

    @task(mode="process", restart=True)
    class MyTask:
        def run(self):
            while self.running:
                pass

  파라미터:
  ┌──────────────┬─────────────┬──────────────────────────────────────────────┐
  │ 파라미터      │ 기본값      │ 설명                                         │
  ├──────────────┼─────────────┼──────────────────────────────────────────────┤
  │ name         │ 클래스명     │ Task 이름 (config의 "id/Name"과 매칭)        │
  │ mode         │ "thread"    │ "thread" 또는 "process"                      │
  │ restart      │ False       │ 오류 시 자동 재시작                           │
  │ debug        │ False       │ 디버그 출력 (아래 2.5 참조)                   │
  └──────────────┴─────────────┴──────────────────────────────────────────────┘


2.2 self가 제공하는 것들
--------------------------------------------------------------------------------

  @task 데코레이터가 자동으로 주입하는 속성:

  ┌──────────────────┬──────────────────────────────────────────────────────────┐
  │ 속성              │ 설명                                                    │
  ├──────────────────┼──────────────────────────────────────────────────────────┤
  │ self.running     │ bool - Task 실행 중 여부 (종료 시 False)                │
  │ self.task_name   │ str  - 이 Task의 이름 (config의 id)                     │
  │ self.signal      │ Signal 체인 객체 (emit/on/off)                          │
  │ self.runtime     │ TaskRuntime - 내부 런타임 (보통 직접 사용 안 함)        │
  └──────────────────┴──────────────────────────────────────────────────────────┘

  config.json에서 주입되는 속성:

  ┌──────────────────┬──────────────────────────────────────────────────────────┐
  │ config 키         │ 주입 결과                                               │
  ├──────────────────┼──────────────────────────────────────────────────────────┤
  │ "client:other"   │ self.other = RmiClient (다른 Task 원격 호출)            │
  │ "task:other"     │ self.other = 직접 인스턴스 (thread 모드 전용)           │
  │ "smblock": "cam" │ self.smblock = SmBlock 풀                               │
  │ "threshold": 128 │ self.threshold = 128  (일반 값)                         │
  │ "@import"        │ 모듈 자동 로딩 (속성 주입 안 함)                        │
  └──────────────────┴──────────────────────────────────────────────────────────┘


2.3 mode 선택 기준
--------------------------------------------------------------------------------

  ┌───────────────┬────────────────────────┬────────────────────────────────────┐
  │               │ thread                 │ process                            │
  ├───────────────┼────────────────────────┼────────────────────────────────────┤
  │ 격리          │ 없음 (GIL 공유)        │ 완전 격리 (별도 프로세스)          │
  │ IPC 방식      │ DirectClient (직접호출)│ RmiClient (SmRingBuffer)           │
  │ 속도          │ 빠름 (~0.01ms)         │ 빠름 (~0.05ms, v2.6 Kernel Wait)  │
  │ 사용처        │ Qt UI, 가벼운 처리     │ CPU 집약, 카메라, 센서             │
  │ 오류 영향     │ 메인 프로세스에 영향   │ 메인 프로세스 안전                 │
  └───────────────┴────────────────────────┴────────────────────────────────────┘


2.4 run() 메서드 규칙
--------------------------------------------------------------------------------

  run()은 @rmi_run이 자동 적용되며, Task의 메인 루프입니다.

    @task(mode="process")
    class MyTask:
        def run(self):                    # 자동으로 @rmi_run 적용
            while self.running:           # 종료 조건 (self.running)
                # 작업 수행
                time.sleep(0.1)           # CPU 양보 필수

  주의사항:
    - run() 안에서 반드시 self.running 체크
    - time.sleep() 없으면 CPU 100% 점유
    - run() 없는 Task도 가능 (RMI 전용 서비스)


2.5 debug 옵션
--------------------------------------------------------------------------------

    @task(debug=True)                     # 전체 디버그
    @task(debug="signal")                 # 시그널만
    @task(debug="method")                 # RMI 호출만
    @task(debug="signal,method")          # 시그널 + RMI
    @task(debug="signal,method,variable") # 전체 (= True)


3. Signal (이벤트 통신)
================================================================================

  Signal은 Task 간 비동기 이벤트 통신 시스템입니다.
  Pub/Sub 패턴으로 1:N 브로드캐스트를 지원합니다.

  특성:
    - 비동기 (emit 즉시 반환)
    - 반환값 없음 (Fire-and-Forget)
    - v2.6: Direct Emit — caller 스레드에서 broker.emit() 직접 호출
    - QoS 5단계 우선순위 (P1 CRITICAL ~ P5 BACKGROUND)
    - Back Pressure: 큐 full 시 재시도 (Signal 무손실 보장)


3.1 Signal 발신 (emit)
--------------------------------------------------------------------------------

  self.signal 체인 문법으로 발신합니다.

    # 기본
    self.signal.score.update.emit({"value": 42})

    # 단순 값
    self.signal.count.emit(self.count)

    # 동적 이름
    name = "a"
    getattr(self.signal.job, name).emit({"id": 1})

  체인 규칙:
    self.signal.<이름1>.<이름2>.emit(data)
    → 시그널명: "이름1.이름2"
    → data: dict, int, str, list 등 pickle 가능한 값


3.2 Signal 수신 - 자동 구독 (on_ 메서드)
--------------------------------------------------------------------------------

  메서드명이 on_ 으로 시작하면 자동으로 시그널 구독됩니다.
  이름 변환 규칙: on_<이름1>_<이름2> → 시그널 "이름1.이름2"

    @task(mode="process")
    class MyTask:
        def run(self):
            while self.running:
                time.sleep(0.1)

        def on_score_update(self, signal):
            """자동 구독: "score.update" 시그널"""
            print(signal.data)  # {"value": 42}

  변환 예시:
  ┌─────────────────────────┬──────────────────────────────────────────────────┐
  │ 메서드명                 │ 구독 시그널                                      │
  ├─────────────────────────┼──────────────────────────────────────────────────┤
  │ on_score_update         │ "score.update"                                   │
  │ on_job_a                │ "job.a"                                          │
  │ on_camera_connected     │ "camera.connected"                               │
  │ on_count                │ "count"                                          │
  │ on_token_returned       │ "token.returned"                                 │
  └─────────────────────────┴──────────────────────────────────────────────────┘

  signal 파라미터:
  ┌──────────────────┬─────────────────────────────────────────────────────────┐
  │ 속성              │ 설명                                                   │
  ├──────────────────┼─────────────────────────────────────────────────────────┤
  │ signal.name      │ 시그널 이름 (예: "score.update")                        │
  │ signal.source    │ 발신 Task 이름                                          │
  │ signal.data      │ 전달된 데이터                                           │
  └──────────────────┴─────────────────────────────────────────────────────────┘


3.3 Signal 수신 - 코드 구독 (on/off)
--------------------------------------------------------------------------------

  run() 안에서 동적으로 구독/해제할 수 있습니다.

    @task(mode="process")
    class MyTask:
        def run(self):
            # 구독
            self.signal.sensor.temp.on(self._handle_temp)

            while self.running:
                time.sleep(0.1)

            # 해제
            self.signal.sensor.temp.off(self._handle_temp)

        def _handle_temp(self, signal):
            print(f"온도: {signal.data}")


3.4 Signal API 요약
--------------------------------------------------------------------------------

  ┌───────────────────────────────────────────────┬────────────────────────────┐
  │ API                                           │ 설명                       │
  ├───────────────────────────────────────────────┼────────────────────────────┤
  │ self.signal.xxx.emit(data)                    │ 발신                       │
  │ self.signal.xxx.on(handler)                   │ 구독                       │
  │ self.signal.xxx.off(handler)                  │ 구독 해제                  │
  │ def on_xxx(self, signal):                     │ 자동 구독 (선언적)         │
  └───────────────────────────────────────────────┴────────────────────────────┘


4. RMI (원격 메서드 호출)
================================================================================

  RMI는 Task 간 동기 메서드 호출입니다.
  다른 Task의 메서드를 마치 로컬 함수처럼 호출합니다.

  특성:
    - 동기 (결과 반환까지 대기)
    - 1:1 호출 (요청-응답)
    - 타임아웃: 2.0초 (config 설정 가능)
    - v2.6: 응답 대기 시 Kernel Event 기반 (CPU 0%, spin-wait 제거)


4.1 config 설정
--------------------------------------------------------------------------------

  config.json에서 "client:<태스크ID>" 로 RMI 클라이언트를 주입합니다.

    "task_config": {
      "worker/MyTask": {
        "@import": "tasks",
        "camera": "client:cam_driver"     ← cam_driver Task의 클라이언트
      },
      "cam_driver/CamDriver": {
        "@import": "drivers"
      }
    }


4.2 메서드 호출
--------------------------------------------------------------------------------

    @task(mode="process")
    class MyTask:
        def __init__(self):
            self.camera = None            # config에서 RmiClient 주입됨

        def run(self):
            # 메서드 호출 (동기)
            frame = self.camera.get_frame()

            # 변수 읽기
            fps = self.camera.fps

            # 인자 전달
            self.camera.set_exposure(100)


4.3 RMI 타임아웃
--------------------------------------------------------------------------------

  config.json:
    "platform_config": {
      "rmi": {
        "timeout": 5.0               ← 전역 타임아웃 (초)
      }
    }

  기본값: 2.0초. 타임아웃 초과 시 RmiTimeoutError 발생.


5. config.json 구성
================================================================================

5.1 전체 구조
--------------------------------------------------------------------------------

    {
      "app_info": {                       ← 앱 기본 정보
        "name": "my_app",
        "id": "node-001",
        "version": "1.0.0"
      },
      "platform_config": {                ← 플랫폼 설정
        "rmi": {
          "timeout": 2.0                  ← RMI 타임아웃 (초)
        },
        "_monitor": {                     ← 웹 모니터
          "port": 7000,
          "exit_hook": true
        },
        "_smblock": {                     ← 공유메모리 풀
          "camera_frames": {
            "shape": [480, 640, 3],
            "maxsize": 10
          }
        }
      },
      "task_config": {                    ← Task 정의
        "id/ClassName": {
          "@import": "module.path",       ← 모듈 자동 임포트
          "client:other_id": {},          ← RMI 클라이언트 주입
          "smblock": "pool_name",         ← SmBlock 주입
          "param_name": value             ← 일반 값 주입
        }
      },
      "user_config": {                    ← 사용자 설정 (자유 구조)
        "interval": 1.0,
        "threshold": 128
      }
    }


5.2 task_config 키 규칙
--------------------------------------------------------------------------------

  "task_config"의 각 엔트리: "태스크ID/클래스명"

    "worker/MyTask": {                    ← ID="worker", 클래스="MyTask"
      "@import": "myapp.tasks"            ← MyTask가 정의된 모듈
    }

  같은 클래스 여러 인스턴스:

    "worker1/MyTask": { "@import": "tasks", "mode": "fast" },
    "worker2/MyTask": { "@import": "tasks", "mode": "slow" }


5.3 의존성 주입 접두사
--------------------------------------------------------------------------------

  ┌──────────────────────┬─────────────────────────────────────────────────────┐
  │ config 키             │ 주입 결과                                           │
  ├──────────────────────┼─────────────────────────────────────────────────────┤
  │ "client:cam"         │ cam Task의 RmiClient → self.client 또는 키 이름    │
  │ "task:cam"           │ cam Task의 직접 인스턴스 (thread 전용)             │
  │ "smblock": "frames"  │ frames SmBlock 풀 → self.smblock                   │
  │ "threshold": 128     │ 일반 값 → self.threshold = 128                     │
  │ "@import"            │ 모듈 로딩만 (속성 주입 없음)                       │
  └──────────────────────┴─────────────────────────────────────────────────────┘

  주의: "client:" 키의 속성명은 콜론 앞 부분입니다.

    "camera": "client:cam_driver"     → self.camera = RmiClient(cam_driver)
    "client:cam_driver": {}           → self.cam_driver = RmiClient(cam_driver)  (키 사용 안됨, 이 형태는 deprecated)


6. GConfig (설정 읽기/쓰기)
================================================================================

  프로세스 안전한 설정 파일 접근. 파일 잠금 기반.

7. SmBlock (공유메모리)
================================================================================

  프로세스 간 이미지/데이터 공유를 위한 고정 크기 메모리 풀.
  O(1) 할당/해제 (Free-List).

  config.json:
    "platform_config": {
      "_smblock": {
        "camera_frames": {
          "shape": [480, 640, 3],         ← H x W x C
          "maxsize": 10                   ← 버퍼 개수
        }
      }
    }

  task_config:
    "processor/ImgProcessor": {
      "@import": "tasks",
      "smblock": "camera_frames"          ← SmBlock 풀 주입
    }

  Task 코드:
    @task(mode="process")
    class ImgProcessor:
        def __init__(self):
            self.smblock = None           # config에서 주입

        def process(self, frame_idx):
            buf = self.smblock.get_buffer(frame_idx)  # numpy 뷰 (Zero-Copy)
            # buf로 이미지 처리
            self.smblock.mfree(frame_idx)             # 사용 후 반환


8. 실전 패턴
================================================================================

8.1 센서 → 처리 → UI (전형적 파이프라인)
--------------------------------------------------------------------------------

  config.json:
    "task_config": {
      "sensor/SensorTask": {
        "@import": "tasks"
      },
      "processor/ProcessorTask": {
        "@import": "tasks"
      },
      "ui/UiTask": {
        "@import": "tasks"
      }
    }

  tasks.py:
    @task(mode="process", restart=True)
    class SensorTask:
        def run(self):
            while self.running:
                data = read_sensor()
                self.signal.sensor.data.emit(data)
                time.sleep(0.01)

    @task(mode="process")
    class ProcessorTask:
        def run(self):
            while self.running:
                time.sleep(0.1)

        def on_sensor_data(self, signal):
            """sensor.data 자동 구독"""
            result = process(signal.data)
            self.signal.result.ready.emit(result)

    @task(mode="thread")
    class UiTask:
        def run(self):
            while self.running:
                time.sleep(0.1)

        def on_result_ready(self, signal):
            """result.ready 자동 구독"""
            update_display(signal.data)


8.2 RMI 체인 호출 (A → B → C → ... → 결과)
--------------------------------------------------------------------------------

  config.json:
    "task_config": {
      "source/SourceTask": {
        "@import": "tasks",
        "relay": "client:mid"
      },
      "mid/RelayTask": {
        "@import": "tasks",
        "next": "client:dest"
      },
      "dest/DestTask": {
        "@import": "tasks"
      }
    }

  tasks.py:
    @task(mode="process")
    class SourceTask:
        def __init__(self):
            self.relay = None

        def run(self):
            result = self.relay.process({"value": 42})
            print(f"최종 결과: {result}")

    @task(mode="process")
    class RelayTask:
        def __init__(self):
            self.next = None

        def process(self, data):
            data["value"] *= 2
            return self.next.process(data)

    @task(mode="process")
    class DestTask:
        def process(self, data):
            data["value"] += 1
            return data


8.3 Signal + RMI 조합 (이벤트 → 상태 조회)
--------------------------------------------------------------------------------

    @task(mode="process")
    class Monitor:
        def __init__(self):
            self.sensor = None            # RmiClient

        def on_sensor_alert(self, signal):
            """sensor.alert 자동 구독"""
            # Signal로 알림 받고, RMI로 상세 정보 조회
            detail = self.sensor.get_status()
            print(f"경고: {signal.data}, 상태: {detail}")

10. RMI vs Signal 선택 기준
================================================================================

  ┌────────────────────┬─────────────────────────┬─────────────────────────────┐
  │ 상황                │ RMI                     │ Signal                      │
  ├────────────────────┼─────────────────────────┼─────────────────────────────┤
  │ "값 가져와"        │ O  count = t.get()      │ X                           │
  │ "이것 처리해"      │ O  t.process(data)      │ X                           │
  │ "상태 변했어"      │ X                       │ O  signal.emit(data)        │
  │ "모두에게 알려"    │ X                       │ O  signal.emit(data) (1:N)  │
  │ "결과 기다려"      │ O  (동기, 반환값)       │ X  (비동기, 반환값 없음)    │
  │ "느슨한 결합"      │ X  (호출자가 대상 앎)   │ O  (이름만 알면 됨)         │
  └────────────────────┴─────────────────────────┴─────────────────────────────┘


11. 주의사항
================================================================================

11.1 process 모드 제약
--------------------------------------------------------------------------------
  - 모든 데이터는 pickle 가능해야 함 (lambda, 소켓 객체 등 불가)
  - 클래스 인스턴스 직접 공유 불가 → RmiClient 또는 SmBlock 사용
  - __init__에서 self.runtime = None 초기화 필요 (직접 runtime 접근 시)

11.2 Signal 주의점
--------------------------------------------------------------------------------
  - Queue 크기 제한: 50 (초과 시 시그널 유실)
  - on_ 메서드명에 주의: on_init, on_error 등 의도치 않은 구독 가능
  - process 모드에서 data는 반드시 pickle 가능해야 함

11.3 RMI 주의점
--------------------------------------------------------------------------------
  - 타임아웃 기본 2초 → 오래 걸리는 작업은 설정 변경 필요
  - 순환 호출 불가 (A→B→A): 데드락 방지를 위해 Exception 발생
  - process 모드에서만 IPC 오버헤드 존재 (~0.05ms, v2.6 Kernel Wait)

11.4 run() 메서드 주의점
--------------------------------------------------------------------------------
  - while self.running 패턴 필수
  - time.sleep() 반드시 포함 (최소 0.001초)
  - run()에서 예외 발생 시 restart=True면 자동 재시작

13. InvokeDispenser (내부 구조, v2.5~)
================================================================================

  v2.5부터 IPC(RMI)와 Signal을 단일 스레드(InvokeDispenser)에서 직렬 처리.
  사용자 코드 변경 불필요 (API 호환 유지).

  동작 원리:
    - Signal 우선 처리 → IPC/RMI 후순 → idle 시 Kernel Wait (CPU 0%)
    - 태스크당 2스레드: InvokeDispenser(1) + Main(1)
    - Deadlock-Free: chain 기반 순환 호출 감지

  개발자 주의:
    ★ on_*() 핸들러 / RMI 메서드 내에서 무거운 연산 금지
      - InvokeDispenser는 단일 스레드이므로 핸들러 실행 중 다른 처리 차단
      - 목표 실행시간: < 1ms (권장), < 10ms (최대 허용)
      - Heavy Compute는 run() 메인 루프에서 수행

  상세 설계: doc/3080.InvokeDispenser설계.txt

14.3 ex040_restart — 자동 복구
--------------------------------------------------------------------------------

  restart=True 설정 시 예외 발생 후 자동 재시작.

  tasks.py:
    @task(name="UnstableTask", mode="process", restart=True)
    class UnstableTask:
        def __init__(self):
            self.run_count = 0

        def run(self):
            self.run_count += 1
            print(f"[UnstableTask] Started (run #{self.run_count})")
            while self.running:
                if random.random() < 0.1:
                    raise RuntimeError(f"Crash at run #{self.run_count}")
                time.sleep(0.5)

    @task(name="WatcherTask", mode="process")
    class WatcherTask:
        def __init__(self):
            self.unstable = None                ← RMI 클라이언트 주입

        def run(self):
            while self.running:
                try:
                    count = self.unstable.run_count   ← RMI로 상태 조회
                except Exception as e:
                    print(f"Unavailable: {e}")        ← 재시작 중 예외 처리
                time.sleep(3.0)

  핵심 포인트:
    - restart=True → 예외 발생 시 자동 재시작
    - run_count로 재시작 횟수 추적
    - RMI 호출 시 Task 재시작 중이면 예외 → try/except 필수


14.4 ex050_select_signal — 선택적 Signal 필터링
--------------------------------------------------------------------------------

  동일 시그널을 여러 Worker가 수신하되 데이터 기반으로 필터링.

  config.json:
    "task_config": {
      "source/SourceTask":   { "interval": 0.5 },
      "worker_a/WorkerTask": { "job_type": "a" },    ← 값 주입
      "worker_b/WorkerTask": { "job_type": "b" },
      "worker_c/WorkerTask": { "job_type": "c" },
      "worker_d/WorkerTask": { "job_type": "d" },
      "dest/DestTask":       { }
    }

  tasks.py:
    @task(name="SourceTask", mode="process")
    class SourceTask:
        job = TSignal(dict, name="job")

        def run(self):
            while self.running:
                job_type = random.choice("abcd")
                self.job.emit({"id": self.job_count, "type": job_type})
                time.sleep(self.interval)

    @task(name="WorkerTask", mode="process")
    class WorkerTask:
        result = TSignal(dict, name="result")

        @on("job")
        def on_job(self, signal):
            if signal.data["type"] != self.job_type:
                return                              ← 자기 타입만 처리
            result = "ok" if random.random() < 0.8 else "ng"
            self.result.emit({"job_type": self.job_type, "result": result})

  핵심 포인트:
    - 같은 WorkerTask 클래스를 4개 인스턴스로 생성 (worker_a~d)
    - config에서 "job_type" 값 주입 → self.job_type으로 접근
    - Signal 핸들러 안에서 데이터 기반 필터링
    - 1:N 브로드캐스트 후 각 Worker가 자기 몫만 처리


14.5 ex060_dynamic_signal — 런타임 구독/해제
--------------------------------------------------------------------------------

  self.signal.xxx.on()/off()로 런타임에 구독을 동적 제어.

  tasks.py:
    @task(name="SensorTask", mode="process")
    class SensorTask:
        sensor_temp = TSignal(float, name="sensor.temp")
        sensor_humidity = TSignal(float, name="sensor.humidity")

        def run(self):
            while self.running:
                self.sensor_temp.emit(round(random.uniform(20, 40), 1))
                self.sensor_humidity.emit(round(random.uniform(30, 80), 1))
                time.sleep(0.3)

    @task(name="MonitorTask", mode="process")
    class MonitorTask:
        def __init__(self):
            self.subscribed = False

        def run(self):
            while self.running:
                if self.subscribed:
                    self.signal.sensor.temp.off(self._on_temp)     ← 동적 해제
                    self.subscribed = False
                else:
                    self.signal.sensor.temp.on(self._on_temp)      ← 동적 구독
                    self.subscribed = True
                time.sleep(5.0)

        def _on_temp(self, signal):
            print(f"temp = {signal.data}")

        def on_sensor_humidity(self, signal):
            """자동 구독: 항상 수신 (on_ 패턴)"""
            print(f"humidity = {signal.data}")

  핵심 포인트:
    - on_sensor_humidity → "sensor.humidity" 자동 구독 (항상 활성)
    - self.signal.sensor.temp.on(callback) → 런타임 구독
    - self.signal.sensor.temp.off(callback) → 런타임 해제
    - 두 방식 혼용 가능 (자동 + 동적)


14.6 ex070_chain_call — RMI 체인 + Signal 토큰 순환
--------------------------------------------------------------------------------

  7-Hop RMI 체인 호출과 Signal 피드백을 조합한 토큰 순환 패턴.

  구조:
    source ──[RMI]──→ mid1 → mid2 → mid3 → mid4 → mid5 → dest
      ↑                                                      │
      └──────────────[Signal: token.returned]─────────────────┘

  config.json:
    "task_config": {
      "source/SourceTask":  { "mid": "client:mid1", "initial_tokens": 10 },
      "mid1/RelayTask":     { "nextTask": "client:mid2" },
      "mid2/RelayTask":     { "nextTask": "client:mid3" },
      "mid3/RelayTask":     { "nextTask": "client:mid4" },
      "mid4/RelayTask":     { "nextTask": "client:mid5" },
      "mid5/RelayTask":     { "nextTask": "client:dest" },
      "dest/RelayTask":     { }                               ← nextTask 없음
    }

  task_source.py:
    @task(name="SourceTask", mode="thread")
    class SourceTask:
        def run(self):
            self.tokens = [f"TOKEN-{i:02d}" for i in range(self.initial_tokens)]
            while self.running and self.round_count < self.total_rounds:
                if not self.tokens:
                    time.sleep(0.001)
                    continue
                token_id = self.tokens.pop(0)
                token = {"id": token_id, "send_time": time.time()}
                self.mid.relay_token(token)           ← RMI 체인 시작

        @on("token.returned")
        def on_token_returned(self, signal):
            round_time = (time.time() - signal.data["send_time"]) * 1000
            self.round_times.append(round_time)
            self.tokens.append(signal.data["id"])     ← 토큰 복귀
            self.round_count += 1

  task_relay.py:
    @task(name="RelayTask", mode="thread")
    class RelayTask:
        token_returned = TSignal(dict, name="token.returned")

        def __init__(self):
            self.nextTask = None                      ← config에서 주입 (없으면 최종)

        def relay_token(self, token: dict) -> str:
            if self.nextTask:
                return self.nextTask.relay_token(token)   ← 중계: RMI 전달
            else:
                self.token_returned.emit(token)           ← 최종: Signal 발신
                return "ok"

  핵심 포인트:
    - 동일 RelayTask 클래스를 6개 인스턴스로 재사용
    - nextTask 주입 여부로 중계/최종 역할 자동 결정
    - RMI 체인: source → mid1.relay_token() → mid2 → ... → dest
    - Signal 피드백: dest → token.returned → source
    - 라운드 트립 시간 측정 (send_time 포함)

14.8 ex110_smblock — 공유메모리 Producer-Consumer
--------------------------------------------------------------------------------

  SmBlock으로 프로세스 간 대용량 numpy 배열 전달 (Zero-Copy 접근).

  config.json:
    "platform_config": {
      "_smblock": {
        "pool": { "shape": [480, 640, 3], "maxsize": 1000 }
      }
    },
    "task_config": {
      "producer1/producer": { "smblock": "smblock:pool", "consumer": "client:consumer" },
      "producer2/producer": { "smblock": "smblock:pool", "consumer": "client:consumer" },
      "producer3/producer": { "smblock": "smblock:pool", "consumer": "client:consumer" },
      "consumer/consumer":  { "smblock": "smblock:pool" }
    }

  task_producer.py:
    @task(mode="process", restart=True)
    class Producer:
        def run(self):
            while self.running:
                image = np.random.randint(0, 255, self.smblock.shape, dtype=np.uint8)
                index = self.smblock.malloc(image)       ← 할당 + 복사
                if index >= 0:
                    self.consumer.on_input(index)         ← RMI로 인덱스 전달
                time.sleep(self.delay)

  task_consumer.py:
    @task(mode="process", restart=True)
    class Consumer:
        def on_input(self, index):
            buf = self.smblock.get_buffer(index)          ← Zero-Copy 참조
            # 이미지 처리...
            self.smblock.mfree(index)                     ← 사용 후 반환

  핵심 포인트:
    - "smblock": "smblock:pool" → SmBlock 풀 자동 주입
    - malloc(image) → 인덱스 반환, 실패 시 -1
    - get_buffer(index) → numpy 뷰 (복사 없음)
    - mfree(index) → 반드시 호출 (누락 시 메모리 누수)
    - 3개 Producer, 1개 Consumer → N:1 패턴


14.9 ex150_dynamic_task — 런타임 Task 생성/삭제
--------------------------------------------------------------------------------

  TaskManager API로 실행 중에 Task를 추가/제거.

  main.py:
    manager = TaskManager(gconfig)
    manager.start_all()

    # 동적 추가
    manager.add_task("worker_1", "WorkerTask")

    # RMI 호출
    client = manager.get_client("worker_1")
    client.ping()                                 → "pong from worker_1"
    client.increment()                            → 1

    # 동적 삭제
    manager.remove_task("worker_1")

    # 상태 조회
    manager.get_status()

  tasks.py:
    @task(name="WorkerTask", mode="thread")
    class WorkerTask:
        def ping(self) -> str:
            return f"pong from {self.runtime.name}"

        def increment(self) -> int:
            self.counter += 1
            return self.counter

        @on(ManagerTask.notify)                   ← 클래스 참조로 구독
        def on_notify(self, sig):
            print(f"received: {sig.data}")

  핵심 포인트:
    - manager.add_task(id, class_name) → 런타임 Task 생성
    - manager.remove_task(id) → 런타임 Task 제거
    - manager.get_client(id) → 동적 Task에도 RMI 접근 가능
    - manager.get_status() → 전체 Task 상태 dict
    - @on(ManagerTask.notify) → TSignal 객체 참조로 타입 안전 구독


14.10 ex130_camera — 산업용 카메라 + SmBlock 뷰어
--------------------------------------------------------------------------------

  IMI 산업용 카메라를 SmBlock으로 Qt 뷰어에 스트리밍.

  구조:
    camera1 (process) ──[SmBlock + Signal]──→ viewer (thread/main)

  config.json:
    "platform_config": {
      "_smblock": {
        "camera_frames": { "shape": [2048, 2448, 3], "maxsize": 100 }
      }
    },
    "task_config": {
      "camera1/imi_cam_driver": {
        "@import": "py_alaska.drives.imi.imi_camera",
        "smblock": "smblock:camera_frames",
        "mac_address": "ff:ff:ff:ff:ff:ff",
        "fps": 900,
        "exposure": 15000
      },
      "viewer/ImiCameraView": {
        "@import": "example.ex130_camera.task_viewer",
        "smblock": "smblock:camera_frames",
        "camera1": "client:camera1"
      }
    }

  패턴:
    카메라 프로세스:
      - ctypes 콜백 → SmBlock.malloc(image) → Signal emit (sm_index)
    뷰어 스레드:
      - on_camera_received → SmBlock.get_buffer(sm_index) → QPixmap → 표시
      - SmBlock.mfree(sm_index) → 버퍼 반환

  핵심 포인트:
    - 카메라 드라이버는 process 모드 (격리)
    - 뷰어는 thread 모드 + main_task (Qt 메인 윈도우)
    - SmBlock으로 프레임 전달 (IPC 오버헤드 최소)
    - Signal은 인덱스만 전달 (경량)
    - mfree 호출 필수 (finally 블록에서)


14.11 ex130b_camera_webcam — USB 웹캠 스트리밍
--------------------------------------------------------------------------------

  산업용 카메라 대신 USB 웹캠(cv2.VideoCapture)으로 동일 아키텍처 구현.

  구조:
    webcam (process) ──[SmBlock + Signal]──→ viewer (thread/main)

  config.json:
    "platform_config": {
      "_smblock": {
        "camera_frames": { "shape": [2160, 3840, 3], "maxsize": 10 }
      }
    },
    "task_config": {
      "camera1/WebcamTask": {
        "smblock": "smblock:camera_frames",
        "camera_index": 1,
        "width": 3840, "height": 2160, "fps": 30
      },
      "viewer/WebcamView": {
        "smblock": "smblock:camera_frames",
        "camera1": "client:camera1"
      }
    }

  핵심 포인트:
    - ex130과 동일 아키텍처 (드라이버만 교체)
    - cv2.VideoCapture로 웹캠 캡처
    - 4K 해상도 시 SmBlock 크기 주의 (24MB/프레임)
    - maxsize 줄여서 메모리 절약 (10개)
